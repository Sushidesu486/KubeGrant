# FreeIPA 用户导入与权限管理

2026-10-16：工作区实现，尚未提交或发布。提交前按用户约定确认。

## 实际目录核验

从 m601 对 IPA 做只读核验：当前 `cn=users,cn=accounts,dc=clusters,dc=zjusct,dc=io` 有 67 个 posixAccount，67 个均有 ipaUniqueID，未发现 nsAccountLock=TRUE。匿名 LDAPS 可读取用户名，但读不到稳定 ID；本地 SASL EXTERNAL 查询证明稳定 ID 实际存在。没有读取密码、修改 IPA 用户或扩大目录访问权限。该核验不等同于已将 67 人导入生产。

用户选择管理员每次导入时在网页重新输入自己的 IPA 密码，不配置或保存常驻目录账号密码。

## 用户操作

管理员进入“用户”页，可以搜索、分页查看全部已登记用户、最近登录时间和有效授权数量。点击“查看权限”查看该用户的集群、角色、期限、凭据策略与实际执行状态，可撤回授权；“分配权限”跳转到预选该用户的授权表单。

“从 FreeIPA 导入”读取全部上述用户容器中的账号，按稳定身份建立或更新记录；包含尚未登录平台的用户，不包含暂存、已删除用户或服务主体。密码仅用于本次经过证书校验的 LDAPS 操作，不持久化。重复导入返回新增、更新、未变更数量。

只同步用户名、姓名与稳定身份，不创建平台管理员身份、会话或 Kubernetes 授权。只有实际登录时的 admins 成员资格决定平台管理员身份。授权仍需管理员显式分配。

## 实现边界

- LDAP 每页 200、最多 10000 人，整体读取超时 12 秒。拒绝缺失稳定 ID、重复 ID/用户名、目录引用、缺少分页控制及任何分页错误；完整读取后才开始一个 SQLite 事务，失败不做部分导入。
- 重新核验的管理员身份必须与当前会话的 provider/issuer/subject 一致，避免同名账号重建后沿用旧身份。落库前在事务内再次核验管理员会话仍然有效。
- 登录与导入共用稳定身份建档逻辑；重命名保留 Member ID 和原授权，同名新 ipaUniqueID 使用新 Member ID，不继承旧权限。
- 导入新增/更新与对应审计在同一事务。未变更用户不重复建立记录。目录导入只增加/更新身份，不删除不在本次目录里的历史成员，也不自动撤回账号停用前已经签发的权限。
- 新用户列表与个人授权列表使用独立分页，不复用原 500 条界面查询。授权表单可接收用户页选中的任意成员。
- 数据库继续使用 schema v2，无新增数据库迁移、Kubernetes RBAC、LDAP ACI、Secret 或网络权限。发布仅更新应用镜像 digest；发布前备份 SQLite。

API：管理员 `GET /api/v1/admin/users?q=&limit=20&offset=0`、`GET /api/v1/admin/users/{id}/grants`、`POST /api/v1/admin/users/import`（仅 password 字段）。沿用会话认证与精确 Origin 校验，导入有次数及并发上限，不接受浏览器上传任意目录用户。

## 验证与发布

已验证：稳定身份、重复导入、重命名与同名重建、无隐式授权/会话、过期或重置会话、超过 500 人分页、搜索字面值、权限隔离；LDAPS 管理员完整读取、普通成员/错误密码/失去管理员资格/CSRF/部分目录读取失败拒绝。前端用本地 67 个模拟用户验证批量导入、分页、搜索、个人权限及预选授权对象，并检查深浅主题。
